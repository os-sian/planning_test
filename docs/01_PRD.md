# 카페 판매·손익·재고 관리 제품 요구사항 문서(PRD)

작성일: 2026-10-12  
상태: PRD v1. 사용자 선택 반영 완료. 배포 대상과 후속 설계 기준은 미정.
합의한 핵심 요구: A안, 본인 단독·여러 기기 사용, 본인만 접근, 매장 운영비 부담을 포함한 메뉴 수익성과 평가 등급, 이미 떨어진 재료 확인, 전체 기록 백업.  
PRD는 프로그램이 누구의 어떤 문제를 해결하고, 어떤 기능을 제공해야 하는지 설명하는 문서다.

## 1. 목표와 사용자

카페 운영자가 판매·비용·재고 기록을 관리하고, 어떤 메뉴에서 돈이 남는지, 선택한 기간의 매장 실적은 어떤지, 어떤 재료가 부족한지 확인한다.

핵심 흐름은 **판매 기록 입력 → 메뉴 수익성 확인 → 기간 손익과 재료 잔량 확인**이다. 기록을 수정하거나 삭제한 뒤에도 이 흐름에서 일관된 결과를 확인할 수 있어야 한다.

사용자가 요청한 전체 목표에는 엑셀 양식 내려받기와 기록 가져오기, 예상 손익, 발주량 참고, 일·주·월·분기·반기·연간 조회, 저장·백업·복원이 포함된다. 아래의 1차·2차 구분은 사용자가 선택한 A안을 반영한다. 전체 목표에서 기능을 제거한 결정이 아니다.

1차는 사용자 본인 한 명이 기록을 입력·수정하는 단독 사용으로 확정했다. 컴퓨터와 휴대폰 등 여러 기기에서 같은 기록을 이어서 사용하는 요구도 확정했다. 매장 기록은 본인만 접근할 수 있어야 한다. 프로그램 주소를 아는 것만으로 다른 사람이 기록을 보거나 바꿀 수 없어야 한다. 접근을 제한하는 구체적인 방법은 정하지 않는다. 한 매장 지원을 제안하며, 배포 대상과 다른 매장 지원 여부는 아직 합의되지 않았다.

## 2. 자료에서 확인한 사실

검토 자료: `매장운영데이터/데이터설명.md`, `매장운영데이터/매장운영데이터.json`, `매장운영데이터/매장운영데이터.xlsx`.

- 매장명은 프렙 카페이며, 직접 구성한 가상 매장 샘플이다. 실제 거래 증빙이 아니다.
- 판매·비용 기록은 2025-07-01부터 2026-09-18까지다. 재고 변동 기록은 2025-07-02부터 시작하며 첫날의 초기재고는 별도로 있다.
- 영업달력은 2026-09-30까지 있고, 9월 19일부터 30일까지 12일은 미마감이다.
- 금액은 원, 부가세 제외 기준이다. 재료 수량의 단위는 g·ml·개다.
- 엑셀과 JSON은 같은 기록을 제공하는 두 형식이다. 두 파일을 별개의 거래 자료처럼 합쳐서는 안 된다.
- 엑셀에는 설명용 `데이터안내` 시트가 추가로 있다. 이 시트는 거래 기록 표가 아니다. `~$`로 시작하는 파일은 엑셀 임시 파일이므로 원본 자료로 취급하지 않는다.

| 기록 | 확인한 수 | 주요 내용과 연결 관계 |
| --- | ---: | --- |
| 공급사 | 3 | 공급사 식별번호와 이름. 재료 및 입고 기록과 연결 |
| 재료 | 11 | 단위, 구매용량, 최초구매가격, 납기·안전재고 영업일, 공급사 |
| 메뉴 | 8 | 메뉴 식별번호, 이름, 판매기준가, 분류, 레시피버전 |
| 레시피 | 22 | 메뉴 1개에 필요한 재료와 사용량, 적용 판매채널 |
| 재료가격이력 | 33 | 재료별 가격 적용시작일, 구매가격, 구매용량 |
| 영업달력 | 457 | 영업 여부, 마감 여부, 날씨, 메모 |
| 판매기록 | 6,112 | 날짜·메뉴·판매채널별 수량, 당시 단가, 할인, 순매출, 수수료, 개당 원가 |
| 초기재고 | 11 | 2025-07-01 영업 시작 전 재료 수량 |
| 재고기록 | 1,515 | 입고 1,302건, 폐기 189건, 실사조정 24건 |
| 월비용계획 | 120 | 2025년 7월부터 2026년 9월까지 월별 비용항목과 금액 |
| 비용기록 | 3,560 | 날짜별 비용항목·금액과 배분기준 |
| 자료정보 | 10 | 출처, 매장명, 기간, 통화 등. JSON에서는 `meta`에 해당 |

ID는 같은 메뉴·재료·공급사·기록을 구별하는 식별번호다. 이름이 아니라 이 식별번호로 자료가 연결되어 있다.

추가로 확인한 사항:

- 판매채널은 매장과 포장이다. 각 채널에 3,056개의 집계 기록이 있다.
- 날짜·메뉴·판매채널 조합의 판매 중복은 확인되지 않았다. 판매·비용·재고 변동의 기록 식별번호에도 중복이 없었다.
- 판매기록의 메뉴 식별번호는 제공된 메뉴에 모두 존재한다. 이 확인이 모든 자료의 품질 검사를 완료했다는 뜻은 아니다.
- 현재 레시피 자료에는 `R1` 버전이 있다.
- 비용항목은 임차료, 인건비, 사업주 부담 보험료, 수도광열비, 관리비, 광고비, 소모품·청소비, 통신·소프트웨어다.
- JSON의 `settings`는 비어 있다. 수익성 분류나 전망 기준 등 운영 정책이 합의된 자료는 없다.

## 3. 기획할 때 주의할 점

| 주의점 | 제품 요구사항에 미치는 영향 |
| --- | --- |
| 판매 한 줄은 주문 한 건이 아니다 | 판매수량을 확인하는 제품으로 기획한다. 주문 건수·객단가는 이 자료만으로 확정할 수 없다 |
| 월비용계획과 일별 비용은 같은 비용의 다른 표현이다 | 손익에서 같은 비용을 두 번 포함하지 않는다. 새 비용 입력과 계획의 관계는 별도 결정이 필요하다 |
| 과거 단가·할인·원가·수수료는 당시 기록이다 | 현재 가격으로 과거 기록을 임의로 바꾸지 않는다. 새 판매와 과거 판매 수정의 원가 처리 기준은 미정이다 |
| 구매가격은 구매용량 전체의 금액이다 | 메뉴 1개당 원가와 혼동하지 않는다. 재료 단위도 유지한다 |
| 포장재는 판매채널에 따라 쓰인다 | 매장 판매와 포장 판매의 재료 사용과 수익성을 구별할 수 있어야 한다 |
| 빈칸과 0의 의미가 다르다 | 미입력 값을 판매 없음·비용 없음·재고 없음으로 단정하지 않는다 |
| 미래 미마감일은 판매 0이 아니다 | 기록된 실적과 아직 기록되지 않은 기간을 구분한다 |
| 연간 기록은 일부 기간만 있다 | 2025년·2026년 자료를 완전한 1년 실적으로 오해하지 않도록 실제 포함 기간을 알린다 |
| 비용기록에는 날짜별 배분 결과가 있다 | 기록 기준 손익을 실제 현금 지출이나 공식 회계 손익과 같은 것으로 설명하지 않는다 |
| 재고에는 증감수량과 실측수량이 있다 | 기록으로 파악한 잔량과 실제로 센 수량을 구분한다. 실사 차이를 반영하는 운영 기준은 미정이다 |
| 납기·안전재고 일수는 영업일 단위다 | 부족 재료와 발주량을 판단할 때 달력 날짜 수로 임의 해석하지 않는다 |

자료에 담긴 과거 원가·수수료·비용 배분은 확인된 기록이다. 앞으로의 계산 정책이나 운영상의 합의로 간주하지 않는다.

## 4. 1차 구현 범위: 4시간 안의 핵심 기능

MVP는 먼저 만들어 실제로 써 보고 유용성을 확인할 최소 핵심 버전이다. 사용자는 **A: 핵심 흐름 우선**을 선택했다. 이후 선택한 여러 기기 사용, 본인만 접근, 운영비 부담을 포함한 메뉴 수익성 및 평가 등급도 아래 1차 범위에 반영했다. 구체적인 운영 기준은 후속 설계에서 정한다.

| 번호 | 핵심 기능 | 사용자가 할 수 있어야 하는 일 | 범위 제한 제안 |
| --- | --- | --- | --- |
| M1 | 제공 자료로 시작 | 기존 메뉴·재료·레시피·가격 이력과 운영 기록을 바탕으로 흐름을 확인한다 | 초기 자료 반영과 반복적인 파일 가져오기는 구분. 기준정보의 직접 편집은 2차 |
| M2 | 판매 기록 관리 | 기존 메뉴의 날짜별 매장·포장 판매 기록을 직접 입력·수정·삭제한다 | 주문별 관리, 새로운 메뉴·레시피 작성은 2차 |
| M3 | 비용 기록 관리 | 비용 기록을 직접 입력·수정·삭제하고 기간 손익에서 확인한다 | 월비용계획 편집과 자동 배분 기능은 2차 |
| M4 | 메뉴 수익성과 평가 확인 | 같은 기간의 메뉴별 판매실적과 매장 운영비 부담까지 포함하여 남는 금액 및 평가 등급을 확인한다 | 비용 포함 항목·나누는 기준·계산식 및 등급 이름·판단 기준은 후속 설계에서 합의. 복잡한 비교와 여러 평가 기준 선택은 2차 |
| M5 | 기간 실적과 손익 확인 | 일별·월별로 기록된 매출·비용·손익을 확인하고 포함 기간을 알 수 있다 | 주·분기·반기·연간 조회 및 예상 손익은 2차 |
| M6 | 재고 기록과 잔량 확인 | 재료의 입고·폐기·실제로 센 재고를 기록하고 판매 이후 재료 잔량을 확인한다 | 하나의 합의된 재고 기준 적용. 발주량 추천과 자동 발주는 2차 |
| M7 | 이미 떨어진 재료 확인 | 현재 재고가 없는 재료를 찾는다 | 기록상 잔량과 실측수량을 구분. 구체적인 판정·재고 처리 기준은 후속 설계에서 합의. 곧 부족해질 재료의 사전 확인은 2차 |
| M9 | 본인만 기록 접근 | 여러 기기에서 본인만 매장 기록을 조회·입력·수정·삭제하고 백업·복원한다 | 접근 제한의 구체적인 방법은 후속 설계에서 결정 |
| M8 | 저장·백업·복원 | 기록을 보존하고 판매·비용·재고와 메뉴·재료·레시피 등 전체 기록을 백업하며 백업한 내용으로 복원한다 | 여러 기기에서 본인의 같은 기록을 사용. 여러 사용자 공동 사용과 자동 백업 이력은 2차 |

사용자는 메뉴에 월세·인건비 같은 매장 운영비의 몫을 부담시킨 뒤 남는 금액을 확인하는 B를 선택했다. 이 요구를 1차 메뉴 수익성에 포함한다. 메뉴 수익성과 매장 전체 손익은 구분하며, 메뉴에 부담시킨 비용을 매장 손익에서 추가 지출처럼 다시 포함해서는 안 된다. 구체적인 비용 포함 항목, 비용을 메뉴마다 나누는 방식, 계산식은 미정이며 이번 문서에서 정하지 않는다.

본인의 여러 기기에서 같은 기록을 이어서 사용할 수 있어야 한다. 기기별로 서로 다른 기록이 고립되는 형태는 이 요구를 충족하지 않는다. 백업 범위는 프로그램의 전체 기록으로 확정했다. 판매·비용·재고 기록과 이를 해석하는 메뉴·재료·레시피·가격 이력·영업달력 등 기준 자료를 함께 보존해야 한다. 공유 방법, 저장 방식, 백업 형식, 복원 시 기존 기록의 취급은 이 문서에서 확정하지 않는다. 다만 저장·백업·복원이 실제로 가능한지는 1차 완료 검사에 포함한다.

### 우선순위 결정

사용자는 직접 입력부터 수익성·손익·재고 확인까지 연결하는 A안을 선택했다. 엑셀 양식·가져오기, 예상 손익, 발주량 추천, 추가 기간 조회는 2차로 둔다. 엑셀 작업을 우선하고 재고 직접 입력을 미루는 B안은 이번 1차 범위에 포함하지 않는다.

## 5. 2차 구현 제안: 확장 기능

| 기능 | 기대 효과 | 먼저 정할 내용 |
| --- | --- | --- |
| 판매·비용 엑셀 양식 내려받기와 가져오기 | 여러 기록을 한 번에 작성하고 옮긴다 | 가져오기 대상, 기존 기록과 중복·충돌이 있을 때의 취급 |
| 주·분기·반기·연간 조회 | 여러 길이의 기간으로 운영을 돌아본다 | 주 시작일, 기간 구분, 불완전한 기간의 비교 기준 |
| 예상 손익 | 아직 마감되지 않은 기간의 결과를 참고한다 | 예상 대상 기간과 전망에 사용할 근거 |
| 재료 부족 사전 확인과 발주량 참고 | 곧 부족해질 재료와 주문할 양을 판단하는 데 도움을 준다 | 예상 사용량, 납기, 여유 재고, 구매 묶음의 취급 |
| 기준정보 관리 | 메뉴·재료·레시피·구매가격의 변경을 반영한다 | 과거 기록 보존과 변경 적용 시점 |
| 월비용계획 관리 | 계획과 기록 기준 실적을 함께 확인한다 | 계획 변경과 이미 기록된 비용의 관계 |
| 수익성 비교 확장 | 여러 기간과 기준으로 메뉴 개선 우선순위를 판단한다 | 비교 목적, 여러 평가 기준 선택, 비용 배분 방식별 비교 범위. 기본 평가 등급은 1차 |
| 여러 사용자 공동 사용과 자동 백업 | 직원과 함께 기록하고 복구 편의성을 높인다 | 사용자별 권한, 공유 범위, 보관 정책 |

자동 발주·외부 결제 기록 연결 등은 현재 요구된 핵심 흐름을 넘어가므로 2차 확정 기능으로 약속하지 않는다.

## 6. 핵심 사용 흐름

1. 운영자가 기존 자료를 확인하고 오늘의 메뉴별 판매를 기록한다.
2. 운영자는 같은 기간의 메뉴 수익성과 평가 등급을 보고 매장 운영비 부담까지 포함한 뒤 어떤 메뉴에서 얼마나 남는지 확인한다.
3. 비용 기록을 확인하거나 보완한 뒤 해당 기간의 매장 손익을 확인한다.
4. 판매와 재고 기록이 반영된 재료 잔량을 확인하고, 이미 떨어진 재료를 찾는다.
5. 입고·폐기·실제로 센 재고를 기록한다.
6. 기록을 저장하고 필요할 때 백업·복원한다.

예시 상황: 오늘 카페라떼 20잔을 판매했다. 운영자는 판매를 기록하고 카페라떼에서 남는 금액, 오늘 또는 이번 달 매장 손익, 우유와 원두의 잔량을 이어서 확인한다. 1차에서는 이미 떨어진 재료를 확인한다. 숫자의 산출 방식과 구체적인 재고 판정 기준은 후속 설계에서 합의한다.

## 7. 1차 완료를 판단하는 기준

아래는 제품이 제공해야 할 결과이며, 계산식이나 상세 검사 절차를 정한 내용은 아니다.

- 제공된 메뉴와 판매 기록으로 핵심 흐름을 끝까지 사용할 수 있다.
- 본인은 여러 기기에서 기록을 사용할 수 있고, 본인이 아닌 사람은 기록 조회·변경과 백업·복원에 접근할 수 없다.
- 판매·비용을 입력·수정·삭제한 결과가 관련 실적과 손익에 일관되게 반영된다.
- 일·월 조회에서 같은 대상 기간의 메뉴 수익성, 매장 손익, 재고 기준일을 파악할 수 있다.
- 메뉴 수익성에는 후속 설계에서 합의한 매장 운영비 부담이 반영되며, 그 비용이 매장 손익에 중복으로 포함되지 않는다.
- 메뉴별 평가 등급을 확인할 수 있다. 후속 설계에서 합의한 하나의 평가 기준을 적용하고, 기준이 미정이거나 필요한 값이 없는 상태를 확정 등급으로 제시하지 않는다.
- 재고 기록과 판매가 관련 재료 잔량에 반영된다. 실제로 센 수량과 기록상 잔량을 구별할 수 있고, 이미 떨어진 재료를 찾을 수 있다. 곧 부족해질 재료의 예측은 1차 완료 조건에 포함하지 않는다.
- 미마감일과 기록 누락을 실적 0으로 오해하지 않고, 일부 기간의 자료임을 확인할 수 있다.
- 엑셀과 JSON의 같은 자료, 월비용계획과 일별 비용을 중복 집계하지 않는다.
- 한 기기에서 저장한 기록을 다른 기기에서 확인하고 이어서 수정할 수 있다. 여러 기기에서 같은 기록을 사용하는지 검사한다.
- 저장 후 다시 사용할 수 있고, 전체 기록을 백업·복원해 핵심 흐름을 재확인할 수 있다. 판매·비용·재고뿐 아니라 그 기록에 연결된 기준 자료도 복구 범위에 포함된다.
- 기준이 미정이거나 필요한 기록이 없는 결과를 확정된 값처럼 제시하지 않는다.

실제 계산 결과의 검사는 별도로 합의한 계산 기준을 바탕으로 준비한다.

## 8. 4시간 작업 예산 제안

| 단계 | 시간 | 끝나야 할 결과 |
| --- | ---: | --- |
| 기획 | 30분 | 1차 범위와 구현에 필요한 운영 기준 합의 |
| 화면 설계 | 25분 | 핵심 흐름에 필요한 정보와 입력 항목 설계 |
| 개발 | 120분 | 핵심 흐름, 기본 평가 등급, 여러 기기 기록 공유, 본인 접근 제한 연결 |
| 검사 | 45분 | 자료 반영, 기록 변경, 핵심 흐름, 여러 기기의 같은 기록 사용, 저장·백업·복원 확인 |
| 배포 | 20분 | 합의된 사용 환경에서 실행하고 사용 가능 여부 확인 |
| 합계 | 240분 | 운영자가 핵심 흐름을 사용할 수 있는 첫 버전 |

이는 목표 시간 배분이지 구현 완료 보장이 아니다. 한 매장, 제공된 기준정보 활용, 단순한 조회와 하나의 합의된 운영 기준을 전제로 한 범위 제안이다. 여러 기기에서 같은 기록을 사용하는 요구를 이 240분에 포함한다. 본인만 기록에 접근하는 요구도 포함한다. 배포 대상은 미정이며 배포 방식과 접근 제한 방법은 여기서 정하지 않는다. 기록 공유, 접근 제한, 메뉴별 운영비 부담과 기본 평가 등급 반영에 필요한 작업량을 확인한 후 시간 안에 어렵다면 줄일 기능을 사용자와 합의한다. 아직 제외한 1차 기능은 없다.

시간이 부족해지면 확장 기능을 먼저 미룬다. 핵심 흐름이나 저장·복원 검사가 끝나지 않은 상태를 완료로 처리하지 않는다. 기획 결정이 길어지거나 배포 요구가 커지면 구현 범위 또는 일정을 다시 합의한다.

## 9. 미정 사항과 질문 진행 방식

질문은 한 번에 하나만 한다. 답변을 받으면 이 문서에 결정 내용과 이유를 반영하고 다음 질문으로 넘어간다. 추천은 합의가 아니며, 답변이 없으면 미정으로 유지한다.

완료한 질문: 1차 우선순위. 사용자 답변은 A이며 문서에 반영했다.

완료한 질문: 기록을 입력·수정할 사람. 사용자 답변은 ‘나 혼자’이며 본인 단독 사용으로 반영했다.

완료한 질문: 사용할 기기. 사용자 답변은 B이며 여러 기기에서 본인의 같은 기록을 이어서 사용하는 요구를 1차에 반영했다. 여러 사용자 공동 사용을 선택한 것은 아니다.

완료한 질문: 기록 접근 범위. 사용자 답변은 A이며 본인만 기록에 접근하도록 1차 요구에 반영했다. 구체적인 접근 제한 방법과 기술은 미정이다.

완료한 질문: 메뉴 수익성의 목적. 사용자 답변은 B이며 매장 운영비 부담까지 포함한 메뉴 수익성을 1차에 반영했다. 비용을 나누는 방식과 계산식은 정하지 않았다.

완료한 질문: 부족 재료 확인의 목적. 사용자 답변은 A이며 1차에서는 이미 떨어진 재료를 확인한다. 곧 부족해질 재료의 사전 확인은 2차로 둔다. 구체적인 재고 처리 기준과 계산식은 정하지 않았다.

완료한 질문: 백업 범위. 사용자 답변은 A이며 프로그램의 전체 기록을 백업 대상으로 확정했다. 백업 형식과 복원 방법은 정하지 않았다.

완료한 질문: 메뉴 수익성 평가. 사용자 답변은 B이며 수치와 함께 평가 등급을 제공하는 요구를 1차에 반영했다. 등급 이름과 판단 기준은 정하지 않았다.

요구사항 수준의 주요 선택을 반영했다. 다음은 남아 있는 사항이며, 이번 문서에서 정하지 않기로 한 계산식·화면·기술·상세 동작을 확정하기 위한 질문은 지금 진행하지 않는다. 후속 설계에서 필요한 시점에 쉬운 예시와 선택지를 주고 한 번에 하나씩 질문한다.

| 구분 | 미정 사항 | 정할 시점 |
| --- | --- | --- |
| 제품 사용 범위 | 배포 대상, 한 매장 지원 여부 | 구현 착수 전 확인 |
| 수익성·손익 정의 | 포함할 비용 항목, 기록 기준 손익의 의미 | 후속 설계 |
| 계산·판단 기준 | 운영비 배분, 원가·수수료 처리, 평가 등급 이름·기준, 재고 처리 | 이번 PRD에서 제외. 후속 설계에서 결정 |
| 기록 보존 방법 | 저장 방식, 백업 형식, 복원 시 기존 기록의 취급 | 이번 PRD에서 제외. 후속 설계에서 결정 |
| 2차 범위 구체화 | 전망·발주·엑셀·추가 기간 조회에 필요한 기준 | 2차 기획 |

미정 사항은 임의로 확정하지 않는다. 구현 전에 필요한 결정이 완료되지 않았으면 해당 결과를 임의 계산하거나 평가하지 않는다.

## 10. 이번 문서에서 정하지 않는 것

계산식, 수수료율, 수익성 등급 경계, 비용 배분 방식, 전망 방법, 재고·발주 계산 방식, 화면 디자인, 기술 선택, 상세 동작, 코드는 정하지 않는다. 관련 주제는 필요한 사용자 의도를 확인한 뒤 후속 설계에서 구체화한다.
